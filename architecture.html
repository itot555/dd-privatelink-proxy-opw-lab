01 · System map

二層 VPC とテレメトリ経路

業務リクエスト、VPC 配置、テレメトリ経路を 3 枚の図に分離して表示する。 業務リクエストは CloudFront → ALB → Frontend/Java → Python → RDS。 Datadog 向け通信は Tenant 内 Interface VPC Endpoint DNS を入口とし、 Proxy NLB 経由で Squid（Metrics/DBM）または OPW（Logs/Traces）へ分岐する。

業務リクエスト（HTTPS） SPA → API（/api/* browser） Squid 経由（Metrics/DBM） OPW 経由（Logs/Traces） Browser RUM（公開 intake）

02 · E2E journey

CloudFront から DB までを一つの経路で確認

ユーザー入口は CloudFront。Java SSI と Python OTel SDK で W3C tracecontext を伝播し、 Synthetics Private Location から同じ経路を API test で検証する。

STEP 01

CloudFront / ALB

HTTPS 入口。ALB SG は CloudFront managed prefix list。

STEP 02

Java（SSI）

03 · Log routing

信号種別ごとに Squid と OPW を使い分ける

Metrics / DBM は常に Squid 経由。Logs / Traces は enable_opw_logs / enable_opw_traces で OPW へ切り替える。 Tenant Agent は Interface VPC Endpoint DNS を共通入口とする。

DEFAULT · SQUID

Metrics / DBM / Process

Agent proxy → EP DNS → NLB:3128 → Squid → PrivateLink
常時有効。Agent proxy → Squid → Datadog PrivateLink。

OPTION · OPW

Logs + Traces

Agent OPW → EP DNS → NLB:8282|:8484 → OPW → PrivateLink
Pipeline ACTIVE + NLB healthy が前提。2026-08 検証済み。

04 · Sandbox sizing

Sandbox サイジング（default）

Squid / OPW は default 1 台（変数で 1〜10、AZ round-robin）。 RDS は Single-AZ。Datadog 本番推奨値とは別である。

Component Count Placement Sandbox default Purpose
Frontend EC2 + Agent 1 Tenant Public t3.small React SPA + RUM（banking demo）
Java + PL Worker + SSI 1 Tenant Public t3.medium REST API、Synthetics、bastion
Python + DDOT + DBM 1 Tenant Private t3.medium OTel SDK、Transaction API、DBM
Squid Proxy 1（max 10） Proxy Private t3.small Metrics/DBM forward proxy
OPW（Logs + Traces） 1（max 10） Proxy Private t3.medium Observability Pipelines Worker
RDS PostgreSQL 1 Tenant Private db.t4g.micro DBM / APM 相関
OPW 再作成時は NLB ターゲット attachment を同一 apply に含めること。 Traces Pipeline は Datadog UI で DRAFT → ACTIVE（Publish）が必要。 Proxy VPC の Private IP は EC2 再作成で変わる — terraform output opw_ssh_commands を参照。 出典: Datadog Agent OP source

05 · SSH & operations

bastion 経由アクセスと運用上の注意

Java EC2 が Tenant / Proxy VPC 双方への SSH 入口（bastion）となる。 Squid / OPW は VPC Peering 経由で Java SG から TCP/22 を許可する。

Target Subnet SSH path 備考
Java / Frontend Tenant Public 直接（allowed_ip / office_ip） PL Worker 同居
Python Tenant Private Java ProxyJump —
Squid Proxy Private Java ProxyJump + Peering proxy_ssh_commands
OPW Proxy Private Java ProxyJump + Peering opw_ssh_commands（IP 変動に注意）
